# Pillar 2 capstone

Extend this Meridian framework. Keep four page objects and three independent tests.

1. Run policy, quote and API scenarios separately, then together.
2. Add one meaningful assertion or one additional fictional data case.
3. Explain why its locator, assertion and data belong in their chosen files.
4. Introduce one labelled classroom failure in a practice copy; preserve the failing report.
5. Read the error and evidence, propose a small repair, review the diff and rerun.
6. Run the final suite in GitHub Actions and download/open the Allure artifact.

Submit code, setup README, successful Actions run link, report artifact and a short failure/repair explanation. Do not submit .env, credentials or private customer information.

Acceptance: independent setup, meaningful assertions, no fixed sleeps, no .only, no weakened assertions, three passing tests, readable named steps and evidence, clean results per run. Retries do not count as repairing a flaky test.

The policy test needs an existing policy owned by the approved training account. Do not purchase a policy. No test saves quotes, changes policies or makes payments. The API check is separate; it does not claim to return the policy used by the UI test.

Copilot is optional. The project works without an AI subscription.
